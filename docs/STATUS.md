# RTS-Design-Research Status

Status: PARTS / DESIGN-LAYER / INVENTORY NEEDED

RTS-Design-Research is the design reference and UI decision material shelf for the RTS ecosystem.

It is a component repository, not RTS core.

It is not RTS-AGE.

It is not a runtime implementation repository.

It is not a design generation engine.

It is not the canonical product UI unless separately promoted.

## Current Position

This repository should hold design references, UI notes, layout explorations, interface research, and design decision material that can later be converted into RTS-compatible implementation proposals.

Design material should remain inspectable and attributable.

UI ideas should be treated as proposals until accepted by a product or runtime repository.

Allowed by default:

- document design references
- add UI research notes
- add layout and information architecture observations
- clarify design assumptions and risks
- organize screenshots or design references when licensing and provenance are clear
- convert design observations into implementation-neutral decision material
- preserve facts, assumptions, unverified material, and open questions separately

Prohibited by default:

- adding runtime implementation code
- adding product UI code by default
- adding copyrighted assets without provenance
- importing RTS core canonical records
- importing RTS-AGE implementation internals
- turning design notes into accepted product requirements without review
- presenting speculative UI notes as canonical decisions
- broad refactors without an inventory decision

## Boundary

RTS defines the protocol and canonical reconstructability rules.

RTS-AGE may prepare implementation artifacts.

Product repositories may accept selected UI proposals.

RTS-Design-Research should remain the design research and decision-material shelf.

## Minimum Alive Definition

This repository is considered Minimum Alive when:

1. Its role as a design research and decision-material shelf is explicit.
2. Its boundaries from runtime, product UI, and RTS core repositories are clear.
3. Its next inventory pass is documented.
4. Asset provenance and assumptions are treated carefully.
5. No runtime behavior or product UI implementation is changed by the rescue documentation itself.

## Current Decision

Keep this repository.

Treat it as a parts shelf for RTS-compatible design research and UI decision material.

Do not expand it into runtime, product UI, asset library, or canonical design system implementation without a separate decision record.
